Part A: Lambda Calculus Computations

Question 1: Lambda Expression Evaluation

Expression 1: (λz. z) (λy. y y) (λx. x a)

Perform beta reduction on (λz. z) with argument (λy. y y):
[z ↦ (λy. y y)]z = (λy. y y)

Now we have: (λy. y y) (λx. x a)
Perform another beta reduction:
[y ↦ (λx. x a)](y y) = (λx. x a) (λx. x a)

Perform beta reduction on the left lambda:
[x ↦ (λx. x a)](x a) = (λx. x a) a

Perform final reduction:
[x ↦ a](x a) = a a

Expression 2: (λx. λy. x y y) (λa. a) b

First reduction (substitute (λa. a) for x):
(λy. (λa. a) y y) b

Internal reduction on (λa. a)y:
(λy. y y) b

Final reduction:
b b

Expression 3: (((λx. λy. (x y)) (λy. y)) w)

First reduction (substitute (λy. y) for x):
((λy. ((λy. y) y)) w)

Perform α-conversion on the internal bound variable to avoid confusion:
(λy. (λz. z) y) w

Internal reduction:
(λy. y) w

Final reduction:
w

Expression 4: (λx. y) ((λy. y y y) (λx. x x x))

Call-By-Value (CBV): In this strategy, we must reduce the argument to a value before substitution. The argument is ((λy. y y y) (λx. x x x)). Its reduction will yield (λx. x x x) (λx. x x x) (λx. x x x), and each additional step will only grow the expression. This is an infinite derivation (divergence), so the expression does not reach a value under CBV.

Call-By-Name (CBN): In this strategy, we substitute the argument as-is without evaluating it first.

[x ↦ ((λy. y y y) (λx. x x x))] y = y
The result is y.

Did we get the same result? No. In CBN we got y, and in CBV the computation did not terminate.

Question 2: Boolean Expressions

Computing test (or tru fls) a b in CBV:

First, evaluate the argument or tru fls:

or tru fls = (λb. λc. b tru c) tru fls → (λc. tru tru c) fls → tru tru fls
tru tru fls = (λt. λf. t) tru fls → (λf. tru) fls → tru

Now substitute into test:

test tru a b = (λl. λm. λn. l m n) tru a b
→ (λm. λn. tru m n) a b
→ (λn. tru a n) b
→ tru a b

Final evaluation:
tru a b = (λt. λf. t) a b → (λf. a) b → a

Definition of nand:

nand = λb. λc. b (c fls tru) tru

Computing nand tru fls:

nand tru fls → tru (fls fls tru) tru → (λt. λf. t) (fls fls tru) tru
→ fls fls tru → (λt. λf. f) fls tru → tru

Computing nand tru tru:

nand tru tru → tru (tru fls tru) tru
→ tru fls tru → (λt. λf. t) fls tru → fls

Question 3: Arithmetic Expressions

c₀ succ in CBN: c₀ ignores its first argument (the function) and returns the second.

(λs. λz. z) succ → λz. z

This is the identity function, which represents c₀ and not c₁.

c₀ succ in CBV: The result is the same. Since succ is a value (an abstraction), it is substituted for s, and the result is c₀.

Definition of isodd:

isodd = λm. m (λb. b fls tru) fls

Calculations:

Let us define not = λb. b fls tru for clarity.

Calculating isodd c₄:

isodd c₄ → (λm. m not fls) c₄ → c₄ not fls

Substitute the definition of c₄:
→ (λs. λz. s(s(s(s z)))) not fls
→ (λz. not(not(not(not z)))) fls
→ not(not(not(not fls)))

Reduction steps:

  1. not fls → (λb. b fls tru) fls → fls fls tru → tru
  2. not tru → (λb. b fls tru) tru → tru fls tru → fls

Back to the expression:

not(not(not(not fls))) → not(not(not tru)) → not(not fls)
→ not tru → fls

Result: fls (Correct, since 4 is even).

Calculating isodd c₅:

isodd c₅ → (λm. m not fls) c₅ → c₅ not fls
→ (λs. λz. s(s(s(s(s z))))) not fls
→ not(not(not(not(not fls))))

Using the reduction logic established above:

→ not(not(not(not tru)))
→ not(not(not fls))
→ not(not tru)
→ not fls
→ tru

Result: tru (Correct, since 5 is odd).

Question 4: Y Combinator

Computing fact c₀:

According to the definition given in the practice, the function uses eq n c₁ as the base case. Since 0 ≠ 1, the code enters the "else" branch where it attempts to calculate times c₀ (fact (pred c₀)).

Since pred c₀ evaluates to c₀, we get c₀ × fact(c₀), which recursively calls fact c₀ again. This leads to an infinite loop. Therefore, the requirement 0! = 1 is not satisfied.

Fix:

We change the stopping condition to check if the number is c₀ explicitly using iszero.

help_fact_fixed = λf. λn. test (iszero n) c₁ (times n (f (pred n)))
